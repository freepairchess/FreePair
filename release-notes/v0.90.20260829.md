# FreePair v0.90.20260829

A big release, and most of it is about getting an event *started* — and
about the two moments that used to make a director doubt the software:
a roster of correct IDs covered in red warnings, and a live board that
said it had been shared but showed nothing.

## What's new

### Share the live board on NA Chess Hub

**The board can now go on a public web page.** Until now FreePair served
the live board from your own laptop, which works beautifully until the
venue Wi-Fi refuses to let devices see each other — which most hotel and
school networks do — or until you close the lid to move rooms.

- **Anyone can open it, from anywhere.** Parents waiting outside, players
  on mobile data, a club's own website. You get a link and a QR code once
  the first copy has landed.
- **It runs alongside the local address, not instead of it.** Two
  separate switches. The local one is the only thing that works with no
  internet; the hosted one is the only thing that works when the venue
  network isolates devices.
- **The page says when it was last updated.** A board that has quietly
  stopped updating is the worst thing this feature could do, so FreePair
  keeps telling the hub it is still there, and the page marks itself
  "not updating" within a few minutes of FreePair going quiet.
- **Closing the laptop does not clear the board.** It adds a "last
  updated" notice and keeps showing the pairings for several hours. A
  lunch break does not blank the screen in the playing hall.

Needs the event to have an NA Chess Hub event ID and upload passcode —
that is what proves the board is coming from you.

**"Wallboard" is now "Live Score Board" throughout**, and sharing it is
no longer described as "publishing", which is a different feature that
sends pairing and result *files*. The two were easy to confuse.

### QR codes, so nobody has to read a web address aloud

**Small codes sit at the right-hand end of the tab row** while you are
sharing — on a section, and on **Event Configuration**, which is where
you are working when somebody first leans over to ask. Click one for a
large, scannable copy with the address written underneath, and a button
that **opens it in your browser on this computer** — useful for checking
the board looks right before the round, or for putting it on a projector.

**Every printed sheet carries them too**, in the header: pairings,
standings, wall charts, prize lists. Tape a pairing sheet to the wall and
a player can scan it and follow the rest of the round from their phone.

**There are two codes because they fail in opposite situations**, and a
player has no way of knowing which situation they are in — the local one
is useless on mobile data, the hosted one is the only thing that works
when the venue Wi-Fi isolates devices. Share both and let people scan
whichever works. If you are only sharing one, only that code appears.

### Work on several players at once

**Ctrl-click or shift-click rows in the roster**, then use **Roster
Update** — the menu says how many you have selected, so it is never a
guess about what it will touch.

- **Edit selected players** changes what a group can genuinely share:
  club, team, state, requested byes, withdrawal. Only the fields you tick
  are changed, so setting the club for eleven players cannot disturb the
  three of them who are on a team.
- **Delete and restore** work on the whole selection. Deleted players
  stay in the file and stay listed, so they can be brought back.
- **Byes replace rather than add.** Everyone selected ends up with
  exactly the rounds you list — which is what "these six are all away on
  Saturday" means.
- **Names, ratings and IDs are not offered.** They identify a player;
  applying one value across a selection would not be an edit.
- **Nothing is ever half-done.** If any part of a change cannot be
  applied, none of it is, and FreePair says so. You never end up with the
  first four players changed and the rest not.

### Quick Event — start an event from a roster file

**A new item under ➕ New Event turns a roster into an event ready to
pair, in one dialog.** Point it at a file, confirm the event and section
names, and start pairing.

- **Reads CSV or plain text**, and copes with files that are not tidy —
  a title line above the table, blank lines, a stray sentence, tabs
  instead of commas.
- **Paste instead, if that is easier.** A second tab takes pasted text,
  lets you edit it, and has a **Check this roster** button so you can see
  what FreePair read before committing to it.
- **Works without a header row.** If nobody labelled the columns,
  FreePair works out which is the ID, which is the rating and which is
  the bye list from the numbers themselves.
- **Byes come across.** A byes column is read as the rounds that player
  has asked *off*, as half-point byes.

**It is also the way out when a web import fails.** If FreePair cannot
read an event's web page, it now says so plainly and offers a route
through instead of a dead end: a ready-made instruction block you can
copy into ChatGPT or another AI tool, which turns a web page into a
roster file Quick Event can read. The instructions are shown in full, so
you can see exactly what is being copied.

### ID verification is faster and stops crying wolf

This is the change most likely to affect your morning.

- **FIDE IDs verify correctly.** A section of FIDE IDs used to show a red
  warning on every row, because the only question FreePair knew how to
  ask was "is this a US Chess member number". Correct IDs were being
  reported as wrong.
- **A number can belong to two federations at once**, and several do —
  the same eight digits can be one player's FIDE ID and a different
  player's US Chess ID. FreePair now works out which federation the
  column holds and reads the ID accordingly, matching on the player's
  name to be sure.
- **Names written either way round now match.** "Zhang Alex" and
  "Zhang, Alex" are the same person. Previously a roster written without
  commas — which is exactly what pasted and AI-assisted rosters look
  like — flagged every single row.
- **A different spelling no longer condemns a correct ID.** Where the ID
  matches exactly but the database spells the name differently, the ID is
  accepted and the spelling mentioned. Transliterated names reach a
  roster by several routes.
- **Much faster**, because IDs are now looked up once, in the right
  place, rather than twice in the wrong one.
- **An offer to tidy the name order.** After verifying, if your roster
  is written "First Last" and the database says otherwise, FreePair
  offers to rewrite the whole roster as "Last, First".

### Advanced pairing options where you can find them

**Accelerate pairings** and **Avoid pairing teammates** now also appear
on the section's **Overview** tab and in the **Edit Section** dialog,
not only in the Pairings-tab window and the round-1 prompt. They are the
same setting in every place.

- **Turning one on fills in its round window for you** — acceleration
  starts at one round, teammate avoidance at the whole event — so you can
  never end up with an option switched on that covers no rounds and
  silently does nothing.
- **After pairing starts they are shown, greyed out, with a note.** "Is
  this section accelerated?" is a fair question mid-event and deserves an
  answer rather than a blank space.
- **The round-1 prompt no longer pre-ticks acceleration** for a section
  that has it switched off. It was reading the leftover round count
  instead of the actual setting, so a section you had deliberately turned
  acceleration off for could be accelerated by pressing Pair.

### Read the release notes inside FreePair

**Settings → Updates** now has a **Release notes** button beside *Check
now* for the version you are running, and a **Notes** button on every
entry in the version list. Useful when a behaviour surprises you and you
want to know whether it changed — and when picking which older version to
go back to, since "the one before boards were renumbered" is easier to
recognise than a date.

**Help → About** also has a **change log** button now, and the version
number can be selected and copied — which is what you actually need when
reporting a problem.

### Check the IDs on the USCF rating report before you file it

The affiliate ID and the two TD IDs are bare codes copied from somewhere
else, and a wrong one is invisible: the export succeeds and the rating
office rejects the submission days later, by which time you are running a
different event.

- **A lookup button beside each of those three fields names who or what
  the ID belongs to** — the club for an affiliate ID, the director for a
  USCF ID — right there in the row. Reading a name you recognise takes a
  second and settles it.
- **Editing an ID clears the name**, deliberately. A name sitting beside
  a number you have since changed looks like the new number was checked.
- **"Not active" is not a typo.** An affiliate that comes back named but
  marked not active means the ID is right and the affiliation needs
  renewing before the report will be accepted.
- **"Couldn't reach" is not a verdict** on the ID either — it means the
  lookup failed. The ID you typed is what gets exported either way.

The dialog also reads better: the labels sit against the fields they
name instead of across a band of empty space, and the ID boxes no longer
resize when an answer arrives.

### Pairing tells you what it is doing

- **No more silent wait before round 1.** Pressing *Pair Round 1* used to
  do nothing visible for several seconds while every player's ID was
  checked. It now says so.
- **One progress window, not two.**
- **A very large section can no longer hang.** The rematch-free pairing
  search is now bounded, so a section of a few hundred players finishes
  in seconds instead of appearing to lock up.

### Smaller things you may notice

- **The taskbar icon is bigger.** The mark was floating in its own
  canvas with an empty band above and below it, so it read as smaller
  than every other pinned app. It now fills the space it is given.
- **The FreePair mark appears in the Help menu.**

## Installer

The installer bundles everything FreePair needs, including the .NET
runtime and both pairing engines. There is nothing to install separately.
Existing installations update in place from **Settings → Updates**.

## Known limitations

These are deliberate trade-offs, not defects.

- **Sharing the live board on NA Chess Hub needs the event registered
  there**, with an event ID and upload passcode. Events that are not on
  the hub use the local network address, which is the whole feature for
  a club night.
- **Quick Event needs you signed in to NA Chess Hub.** The menu item is
  visible but disabled otherwise, and says why.
- **ID verification covers US Chess, FIDE, CFC and NWSRS.** An ID from
  another federation is left unchecked rather than guessed at — reported
  as "not verified", which is not the same as "wrong".
- **Acceleration and teammate avoidance lock once round 1 is paired.**
  Both change what round 1 does, so switching either on afterwards would
  describe a tournament that had not been run. The round windows stay
  adjustable until the rounds they cover have been paired.
- **A small number of SwissSys-fidelity differences remain** in board
  ordering and in bye choices that SwissSys makes at the director's
  discretion. These are known, tracked, and do not affect the legality of
  a pairing.
- **Bulk roster edits cover shared fields only**, and bulk delete is
  reversible only until the section is paired — the same rule that
  applies to deleting one player.
- **The ID lookups on the rating-report dialog need a connection.**
  Nothing is checked automatically, and nothing is blocked when a lookup
  cannot be made: what you typed is what gets filed.
