# FreePair v0.60

A **Roster-tab fix release**. ID verification no longer flags correct IDs in
online events, and the optional-column chooser now explains itself — with a new
option to show columns that are still empty.

## What's new in v0.60

### ID verification works for online events

- **Correct IDs are no longer flagged red.** In online events, player names carry
  the site handle — for example `Delchev [dxxxx], Ivan`. FreePair compared that
  whole string against the federation's record, so the name never matched and
  every player came back with a red warning even though their IDs were right.
  Handles are now ignored when matching names.
- **A red warning means something again.** When every player is flagged, the
  warning is noise you learn to skip past. Now a flag points at a genuine
  problem — a wrong ID, or an ID belonging to somebody else.

### Optional columns explain themselves

- **Columns with nothing in them say so.** A column that no player has a value
  for is dimmed in the Optional Columns chooser and labelled *"ID2 — no data in
  this section"*. Previously you could tick ID2 or Rating2, see nothing appear,
  and reasonably conclude the setting was broken. It was hiding the column on
  purpose to save space, without telling you.
- **New "Show empty columns" option.** Off by default. Turn it on when you're
  about to type those values in, or you want the column on a printed roster, and
  ticked columns appear even while they're still blank. The choice is saved with
  the section, so each section can differ.

## Known limitations

- **Re-run "Verify ID" to clear old warnings.** Players flagged by the previous
  build keep their mark until you verify the section again in this one.
- **Name matching still requires the real name.** Handles in brackets or
  parentheses are ignored, but a player entered under a nickname the federation
  doesn't know will still be flagged — which is the intended behaviour.
- **"Show empty columns" is per section.** Turn it on in each section where you
  want it; it isn't an application-wide preference.
