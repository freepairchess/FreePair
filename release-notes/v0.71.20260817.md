# FreePair v0.71.20260817

## What's new

### Standings now number opponents the way US Chess does

- **Round codes name the opponent's place in the standings.** `W7B` means
  a win with Black against whoever is standing 7th — the row numbered 7
  in the new **#** column, on the same sheet. Previously the code named
  the opponent's pair number, which on a table sorted by score points at
  no row the reader can see.
- **This is what a player expects.** The published US Chess crosstable
  and NA Chess Hub both number rows by standing and reference opponents
  by that number. A player checking their result against either was
  comparing numbers that did not correspond, and had no way to know why.
- **The # column is always shown, and is not the Place column.** Places
  tie: five players level on score all read "2-6", and only the first row
  shows it. An opponent reference has to name exactly one row, so it gets
  a column of its own that is never blank and never shared.
- **The filter box searches it.** Reading `W7B` and wanting to know who 7
  is, type 7.
- **The wall chart still uses pair numbers**, deliberately. It is ordered
  by pair number and shows that column, so a reference there points at a
  row you can find on the page. Each sheet cites the number its own
  reader can look up.
- **Nothing that gets submitted changed.** The rating report files
  results by pair number exactly as before.

### Team standings match

- **Team standings carry the same # column**, and their round codes cite
  the opponent's row rather than the opponent's seed. Team places tie in
  the same way — four teams level on match points all read "1-4" — so the
  same reasoning applies.
- **The team wall chart keeps seeds**, being ordered by seed and showing
  the Seed column.

### Fixes

- **Team match results now update when the last board is entered.** A
  match with every result in could still read "In progress" on the Team
  Pairings tab while the team standings had already scored it. The
  standings were right; the pairings tab was showing a stale line.
- **The grid text-size number keeps up with the buttons.** Making grid
  text bigger or smaller resized the text but could leave the number
  between the A− and A+ buttons stuck at an earlier value, so the readout
  disagreed with what was on screen.

## Installer

- Windows installer, single file. Bundles the .NET runtime and both
  pairing engines — nothing to install separately.
- The user guide and the USCF rules reference are installed with the app.
- Updates from an earlier version in place; your settings and recent
  events are kept.

## Known limitations

- **This release is Windows only.** macOS and Linux builds were not
  produced for this version; the previous cross-platform release remains
  available for those.
- **Merging sections is new and lightly exercised.** It arrived in the
  previous release and has not yet been run through a full live event. It
  renumbers the whole combined field, so if you use it, check the
  standings and wall chart against your own record before publishing.
- **The team-event fixes above were verified by automated tests rather
  than by running a team event.** They are correct as far as the tests
  reach; a real team event would be worth a careful look.
- **Pairing numbers still cannot be renumbered mid-event.** A player
  added after the event starts takes the next free number rather than the
  one their rating would earn. Pairings are correct either way; it is the
  numbering on a submitted crosstable that a strict reading would
  question.
- **Offline rule and help links have been verified on Windows only.**
