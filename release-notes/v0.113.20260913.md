# FreePair v0.113.20260913

## What's new

### Round 1 pre-pairing tasks are now a choice

- **The Start Pairing R1 window opens ready to pair.** The three optional
  preparation tasks — roster sync, ID verification, rating refresh — sit behind
  a tick-box beside **Pre-Pairing Tasks (Optional)**, and it starts clear. The
  window's job is to pair round 1, and it no longer opens looking like a
  checklist you have to work through first.
- **Clear means skipped, not hidden.** Those tasks reach out to NA Chess Hub
  and can change ratings, so none of that happens behind a collapsed panel.
  Tick the box to bring the table back exactly as it was.
- **Pair All Sections has the same switch, on by default.** Pairing one section
  at a time, you are already looking at it. Pairing the whole event in one
  click *is* the sweep these tasks are for, and there is no other moment to ask
  for it. Untick it and no section prepares — so you get the same roster
  whichever way you pair.
- **The switch covers everything that goes online before round 1**, including
  this event's own pre-pairing rating check. With it clear, nothing is looked
  up before a round is paired.

### The roster question is asked once, before anything is paired

- **One review for the whole run.** If your event is linked to NA Chess Hub, a
  batch run now downloads the roster and shows you a single review before it
  pairs anything, instead of interrupting between sections — after some rounds
  already exist and before others do.
- **A section whose roster changes you did not apply is left unpaired**, and
  its row says what to do about it. Pairing round 1 without a player who
  registered is undone only by deleting the round and pairing again, so
  FreePair leaves the section alone: that costs you a second look instead of
  the round.
- **A section that pairs, stays paired.** Anything else the preparation found
  appears as a note under the row with the full detail on hover. The pairing
  safety checks are separate from all of this and always run.

### Forfeits no longer disturb the colour due

- **A forfeited round shows as `X` and does not count toward colour.** No game
  was played, so it gives a point and not a colour. A player who had Black in
  round 1 and a forfeit win in round 2 now reads `BX` and is still due **W**.
- **This is the same view the pairing engines already had**, so the colour
  shown beside a player now matches the colour you are handed next round.

> **Record a forfeit as a forfeit.** The result box offers **1-0F**, **0F-1**
> and **0F-0F**. Entering one as a plain **1-0** makes it a played game
> everywhere: its colour enters the balance and the two players count as having
> met, which changes future pairings under both FIDE and US Chess rules.

### Making teams from family names

- **Put siblings on one team in a step.** **Make Teams With Same Family Name**
  places every player sharing a surname onto one team, which is what **Avoid
  pairing teammates** then works from. It is on **Event Operations** for the
  whole event and on a section's **Roster Update** for one section.
- **You see every change before anything happens** — each player, the team they
  have now, and the team they would get — and the whole batch is one **Undo**.
- **Name the teams your way** with a `{family}` pattern, and choose whether to
  overwrite teams players already have. That is off by default, and anyone kept
  as they are is listed so you can see them.
- **A surname held by one player in a section is left alone**, because there is
  nobody to keep them apart from.

### Finding players in the player database

- **Searching a full name no longer hides the right player.** Searching *David
  W. Martin* used to return every *David Martin* and not the one you spelled
  out. Both an exact and a close match now run, and the results are merged with
  the closest names first.
- **The search starts when the window opens**, from the name you already typed
  into the Add-player form.
- **Narrow a long list without searching again.** A new filter box sifts the
  rows already on screen and matches any column, so a middle initial, a state
  or part of an ID all work.

### Event configuration

- **The NA Chess Hub tab is now Online**, because the rating-database check on
  it is not a NA Chess Hub feature and a tab named for one service was the
  wrong place to look for it.
- **Credentials come first, and what depends on them stays hidden until both
  are filled in** — no more tick-boxes that silently cannot do anything.
- **Alert when NA Chess Hub roster has updates to sync is now per event.** A
  club night whose roster is settled and a weekend still taking entries at the
  desk want opposite answers, and both are run from the same machine. New
  events follow your default under **Settings → Online**; how often the check
  runs stays an app setting.
- **Before pairing** groups requiring check-in with the rating-database check.

### Smaller things

- **Sign out, or switch account, from the My Events window itself.** That is
  where you find out you are signed in as the wrong account, so it is where the
  way out belongs.
- **A ChessReg roster link brings the event dates with it.** Paste
  `…/roster` and the event's own page is read too, so the event arrives
  pairable — FreePair will not pair round 1 without a start date.
- **The collapsed section list is readable again.** It showed about three
  characters, which made *U1700* and *U1200* look the same. It is wider now,
  shows as much of each name as fits, and the divider resizes it while
  collapsed.
- The **Search Player DB** button matches the height of the buttons beside it.

## Installer

- **Windows x64 only.** Run `FreePair-win-x64-Setup.exe`. The installer
  includes the .NET runtime, both pairing engines and the updated user guide.
  Keep your normal event backups before updating.
- **Signed as Chessnique LLC.** The local Windows release process signs and
  timestamps the installer and packaged executables before publication.
- **macOS and Linux remain on v0.109.20260910.** This release does not replace
  their existing packages.

## Known limitations

- **Family teams are a roster label, not a team event.** They fill in each
  player's team so **Avoid pairing teammates** can use it. Turning that on is
  still your decision, and it cannot be changed once a section has paired
  round 1.
- **Teams are grouped per section**, because players in different sections
  can never be paired against each other.
- **A forfeit only stops counting for colour if it is recorded as one.** A
  forfeit entered as an ordinary result is treated as a played game, and no
  later correction to the display will undo that.
- **The pre-pairing tasks are optional by design.** With them switched off,
  nothing is checked online before a round — including late entries. The
  pairing safety checks still run either way.
- **Existing pairing differences remain.** This release does not change the
  pairing algorithms or their deliberate differences from SwissSys.
- **Windows security prompts can still appear.** Signing does not override
  SmartScreen, antivirus policy or administrator permissions.
