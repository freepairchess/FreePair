# FreePair v0.100.20260904

## What's new

**Everything on a player's row now moves with the player.** The previous
release stopped IDs and ratings from sliding to the wrong person when a roster
is re-seeded, and it did that by rewriting each of those values from the
player it belongs to. This release fixes the reason they slid at all.

FreePair edits your `.sjson` file in place, patching the fields it manages and
leaving everything else exactly as it found it — that is how information
FreePair does not display survives a save. It used to find each player's row
by seed number, which is precisely the thing re-seeding changes. So a player
was written into whoever previously held their number, and any detail FreePair
does not itself manage stayed on the row instead of following the person.

FreePair now finds each player by **who they are** — their US Chess, FIDE, CFC
or NWSRS ID, then their name, and only then their seed number. Everything on
the row travels with them, including details FreePair does not show you.

**Age travels with the player again.** On a non-NWSRS event, age was one of
the details still tied to the row. It affects age-prize eligibility, and it is
correct now.

**Re-seeding sticks.** A related fix: because a re-seeded player is now found
in their original row, their new seed number has to be written back
explicitly. It is. Previously this could not go wrong, and now that it can,
it is covered by tests both ways.

**Deleting a player deletes the right one.** When you remove a player,
everyone below them is renumbered — which meant the removed player's seed
number instantly belonged to somebody else. Removal is now tracked by the
player, not the number. Players you have marked deleted-but-kept are
untouched, as before.

## Recommended after upgrading

**If you re-seeded an event under an older build and have not yet submitted
it, open it and check a few IDs on the Roster tab before you report.**
FreePair writes each player's own IDs back on save, but it cannot know what an
already-saved file *should* have contained.

## Installer

Windows installer bundles the .NET runtime — nothing else to install. Run it
and FreePair updates in place, keeping your settings and recent events.

## Known limitations

**Section renaming.** Sections are still matched by name. Renaming two
sections to each other's names within a single session would swap their
contents. This has never been reported and takes a deliberate sequence to
reach; it is noted here for completeness.

**Curated pairing-fidelity cases.** A small set of comparisons against
SwissSys output remain deliberate trade-offs — board ordering within a score
group, and bye selections SwissSys makes at its own discretion. They do not
affect the legality of a pairing.
