# FreePair v0.86.20260826

**Linux and macOS are back.** This release carries builds for Windows,
Linux and both Intel and Apple-silicon Macs — the first time since
v0.81 that every platform is covered. If you have been holding on
v0.81.20260823 waiting for your operating system, this is the one to
update to, and your in-app update check will find it.

The rest of this release is about speed on a big event, and nothing
else. No rules changed, no file format changed, and nothing moved in the
menus.

A director running a large section reported that FreePair had become
sluggish — that moving between the tabs of a section took a noticeable
moment every time, and kept taking it even after they had already been
to every tab once. The cause turned out to have nothing to do with how
big the file was. Every table in a section was drawing **every row it
had**, whether or not those rows were anywhere near the screen, and
throwing them all away and redrawing them each time you changed tab. A
section with two hundred players did roughly twice the work of one with
a hundred, for the same one screenful of table you could actually see.

That is fixed. A table now draws the rows that fit on your screen and no
more.

## What's new

### Moving around a large section is quick again

- **Switching tabs is now about twelve times faster** on a full section,
  and — the part that matters more — **it no longer gets slower as your
  event gets bigger**. A two-hundred-player section changes tabs in the
  same time as a twenty-player one, because the work depends on the size
  of your screen rather than the size of your roster.
- **Entering a result only recalculates the section you are working in.**
  Scoring a board in one section used to rebuild the standings, wall
  chart and roster of every other section in the event as well. In a
  multi-section event that was most of the cost of every single result
  you typed.
- **Opening an event is faster**, for the same reasons.

### The big tables now fill the window

On **Roster**, **Pairings**, **Standings** and **Wall Chart**, the table
stretches to the bottom of the window and scrolls inside itself. The
toolbar and the filter box above it stay where they are while you work
down a long list, instead of scrolling away off the top.

- **Make the window bigger and the table gets bigger.** Move FreePair to
  a larger monitor and it uses the room — more players visible at once,
  rather than the table staying whatever size it was.
- **The sideways scrollbar is reachable.** The roster is a wide table,
  and its horizontal scrollbar used to sit at the bottom of the full
  list — thousands of pixels below the screen on a long section, so
  getting to the columns on the right meant scrolling the whole page
  down first. It now sits directly under the table.

Overview, Prizes and Norms are unchanged: those are stacks of cards
rather than one big table, so they still scroll as a page.

### An hourglass while FreePair is working

The pointer becomes a wait cursor while an event is opening or the
pairing engine is running, so a pause that is FreePair thinking is
distinguishable from one where your click did not land. It is
deliberately not used for anything that finishes quickly — a cursor that
flickers on every keystroke tells you nothing.

## Installer

Each platform gets its native installer, with the .NET runtime and the
FIDE pairing engine bundled — nothing else to install first.

- **Windows:** `FreePair-win-x64-Setup.exe`. Adds a Start Menu entry and
  an uninstaller, and updates itself from this feed.
- **macOS:** `FreePair-osx-arm64-Setup.pkg` (Apple Silicon) or
  `FreePair-osx-x64-Setup.pkg` (Intel)
- **Linux:** `FreePair-linux-x64.AppImage` — make it executable and run
  it; no installation and no root needed.

Portable zips are attached for anyone who prefers not to install.

## Known limitations

**Files**

- **Nothing about your events changed in this release.** The file format
  is untouched, so a file saved by this version is identical in every way
  to one saved by v0.85, and you can move back and forth between the two
  builds freely.

**Speed**

- **The gain is in moving around and in entering results**, not in
  pairing. Pairing time is the FIDE engine's, and this release does not
  touch it.
- **Very long events have not been measured.** The improvement was
  verified up to two thousand players across eight sections at nine
  rounds. An event with substantially more rounds than that has more
  wall-chart columns, and that case has not been timed.

**Platforms**

- **FreePair is not code-signed or notarised.** Windows SmartScreen may
  warn on first run — choose "More info" then "Run anyway". macOS shows a
  Gatekeeper warning; open System Settings → Privacy & Security → Open
  Anyway. Note that macOS 15 removed the Control-click bypass.
- **The Linux and macOS builds have had far less use than the Windows
  one**, simply because almost every director running FreePair so far has
  been on Windows and the last four releases were Windows-only. The
  pairing engine and the file handling are the same code on every
  platform; it is the look of things — fonts, icons, dialog sizes — that
  has had the least exercise. Reports are welcome.
