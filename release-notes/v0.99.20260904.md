# FreePair v0.99.20260904

## What's new

**Player IDs and ratings now stay with the player when a roster is
re-seeded.** This is the important one. Re-seeding — which happens on the
recommended path to pairing round 1 — could leave each player's US Chess ID,
FIDE ID, CFC ID and the ratings behind them attached to the row rather than
to the person, so they slid one place down the section. Because the US Chess
ID is the identity a rating report submits under, an affected event could
have reported games against the wrong member numbers. Everything a player
carries now moves with them.

**If you have re-seeded an event and not yet submitted it, open it, save it,
and check a few IDs on the Roster tab before you report.** Saving with this
build writes each player's own IDs back; it cannot repair an event that was
already saved and closed, because the wrong values are what the file now
contains.

**NWSRS ratings refresh properly.** On an NWSRS-rated event, *Refresh
Ratings* would report that every rating already matched and change nothing.
It now fetches each child's current NWSRS rating, updates the roster, the
NWSRS column and the printed reports together, and the new value survives
saving and reopening.

**Ratings are compared against the right federation.** A FIDE-rated section
keeps the FIDE ID and rating in the pairing columns and the US Chess pair
beside them. FreePair now reads each column's federation from the file and
compares like with like, instead of assuming the first column is US Chess.
Dual-rated events have both columns checked, each on its own row, so a player
whose FIDE and US Chess numbers have both moved is shown both.

**The supplement check stopped lecturing.** Pairing an event dated in a past
month — an old file you are rehearsing with, or a weekend event that has run
into a new month — now raises nothing at all: such an event keeps the
supplement it started on, so the only advice was ever "change nothing". An
event starting later this month or beyond is compared against the current
supplement, which is what round 1 would be seeded on either way. FreePair
still refuses to pair round 1 without an event start date.

**The check is now on by default**, and stays silent on every event it has
nothing to say about.

**Nothing about the rating check can cost you a round.** If the service is
down, slow, on last month's supplement, or knows none of your players, the
round pairs anyway and the status bar says why. The check is given 30 seconds
and then abandoned — an unbounded wait is worse than an outage.

**Pairing a section now tells you what it is doing.** Verifying IDs and
checking ratings are a request per player, so a large section spends real
time there. The panel names the step and counts players — *18 of 35* — rather
than leaving you looking at an unchanged window.

**Rating lookups are much faster.** Whole-roster checks now go out in one
request per federation instead of one per player, and FIDE detail lookups
batch on both ID types, so a section that took the best part of a minute
resolves in about a second.

**Your own alert sound.** The NA Chess Hub alert can now play a `.wav` or
`.mp3` of your choosing — useful when something else on the machine already
beeps, or when the hall is loud. Nothing plays until you press **Test**.

**The alert only sounds when there is something new.** It used to make its
"come and look" noise again when you had just dealt with the changes.

**Settings no longer lose your recent-events list.** Changing any setting
could revert the recent-events list, the last-opened file, window positions
and print settings to whatever they were when the Settings tab was opened.

**The event card was rebuilt** so the event name has the full width and the
organiser's logo sits beside the location and dates, large enough to
recognise.

## Installer

Windows x64. The installer bundles the .NET runtime and the FIDE (bbpPairings)
and US Chess pairing engines, so there is nothing else to install. It creates
a Start Menu entry and an uninstaller, and updates itself from this feed.

## Known limitations

- **Age on a non-NWSRS event still follows the row rather than the player.**
  FreePair does not model that field, so it cannot yet be moved with its
  owner. It affects age-based prize eligibility only. Every ID and rating is
  fixed.
- **A file already saved with mis-associated IDs cannot be repaired
  automatically.** The correct values are not in the file any more. Re-import
  the roster from NA Chess Hub, or correct the affected players by hand.
- The curated SwissSys comparison harness still carries a small number of
  deliberate differences in board ordering and discretionary bye choices,
  unchanged by this release.
