# FreePair v0.75.20260821

**This release fixes four ways FreePair could damage your event file.**
Three of them were found by a tournament director running a real event.
If you are on an older build, please update before your next tournament.

It is also the first release built for **Windows, Linux and macOS**
together in a while, so Linux and macOS TDs get all of the above.

---

## Please read this first

Two of these defects wrote bad data **silently** — the screen looked
right and the saved file was wrong. If you have run an event on a recent
build, it is worth a look:

- **Open your event and check your section list.** If you renamed a
  section, the file may contain extra copies of it that FreePair does not
  show until you reopen the event. Delete any duplicates before
  submitting a rating report.
- **Check results in any round you clicked back to.** Switching to an
  already-played round could overwrite results on boards you never
  touched. **Event Operations → 📓 Decision Log** lists every result that
  was changed after being entered. It will *not* list a result written
  onto a blank board, so check those against your paper scoresheets.

FreePair cannot repair a file that was already damaged. The fixes stop it
happening again.

## What's new

### Northwest Scholastic Rating System (NWSRS)

- **Full NWSRS support** — FreePair reads NWSRS ids, school and grade,
  looks players up against the NWSRS service, and labels the data clearly
  so an NWSRS rating is never mistaken for a US Chess one.
- **Export NWSRS Report** on **Event Operations** writes the file NWSRS
  rates from, in SwissSys's own format, with FreePair's private entries
  removed. It refuses to export an event with no games rather than
  sending an empty submission.
- **A malformed file now tells you what is wrong and pairs anyway**,
  instead of refusing to open.

### Printing the whole event at once

- **🖨 Print All Pairings / Standings / Wall Charts / Crosstables** on
  **Event Operations** — one PDF covering every section, instead of a
  trip through each section tab.
- **Several crosstables per page.** A quad's crosstable is four rows, so
  ten quads used to cost ten near-empty sheets. Stack 2, 3 or 4 down a
  landscape page instead. More per page means smaller print and less room
  to write results in by hand; print one per page when you want that
  room.
- Each print asks which sections to include, then shows the same **Page
  setup** every other print button does — so type size and orientation
  you tuned on a section tab are the ones the event-wide sheet uses.

### Choosing what goes into a rating report

- **USCF, FIDE and NWSRS exports now ask which sections to include.**
  Everything reportable starts ticked, so press Continue and nothing
  changes. Untick a side-game, a practice group, or a section you made to
  try something out — **without deleting it** from your own records.
- Sections that cannot be reported are listed with the reason shown, so a
  section is never quietly missing.

### Seeing where a round stands

- **The Round list now marks each round** — a green tick when every game
  has a result, an amber hourglass for the round being played, nothing
  for a round still ahead. Most useful in a quad or round robin, where
  every round is paired at once.
- **The wallboard follows the round actually being played.** For a round
  robin or quad it now shows the first unfinished round and moves forward
  by itself as results come in. It used to show the final round from the
  moment the section was paired, sending players to boards they were not
  due at for hours.

## Fixed

### Your event file

- **Renaming a section no longer renames its neighbours.** Finishing a
  rename moved the panel to a different section, which then had the name
  you had just typed written onto it — and again, and again, walking down
  your section list.
- **Saving no longer adds copies of a renamed section.** Every save after
  a rename appended another copy, silently, for as long as the event
  stayed open. FreePair kept showing the right number, so this was only
  visible on reopening. An eight-player event was reported with **40
  sections** on disk.
- **A re-split section is no longer lost.** Re-pairing a section into
  quads after renaming the first set could leave the new quads on screen
  but absent from the saved file.

### Entering results

- **Switching rounds no longer changes results.** Clicking back to an
  already-played round could write the previous row's result onto boards
  nobody had touched.
- **Results are recorded again.** A fix for the above briefly discarded
  every result picked from the drop-down — the grid showed it, nothing
  was saved, and the round would never complete.
- **Changing a bye kind works again**, which had been silently doing
  nothing.
- **The upset highlight appears immediately.** The colour marking a
  lower-rated player's win only showed up after pairing another round and
  coming back.

### SwissSys compatibility

- **Files FreePair saves open in SwissSys again.** FreePair wrote empty
  values in a form SwissSys rejects outright, which made a
  FreePair-authored file unopenable there.
- **Section player counts match the roster beneath them**, which a strict
  reader needs in order to load the file at all.

### Smaller things

- A freshly paired quad or round robin opens on **round 1**, not its last
  round.
- **"Pair Next Round"** says why it is unavailable instead of describing
  what it would do.
- The section choosers use the width they are given instead of clipping
  the progress text.

## Installer

The Windows installer bundles the .NET runtime — nothing to install
first. Linux and macOS builds are attached to this release.

Existing installs update in place and keep your settings.

## Known limitations

**Deliberate trade-offs, not defects:**

- **Pairing fidelity.** FreePair reproduces the great majority of
  pairings from a large real-world SwissSys corpus, reaching 100% on many
  representative events. The remainder are cases where the USCF rules
  permit more than one correct answer — board ordering within a score
  group, and which player receives a bye when several are equally
  eligible.
- **Already-damaged files are not repaired.** The fixes above prevent new
  damage; a file that already carries duplicate sections needs the extras
  deleted by hand.
- **Crosstables are for all-play-all sections only.** A Swiss field never
  meets everyone, so its crosstable would be mostly empty — print the
  wall chart instead.
- **Some session settings are not saved with the event** — do-not-pair
  pairs, forced pairings and a few pairing toggles apply for the session
  only.
