# FreePair v0.101.20260904

## Please upgrade

**This release completes a run of fixes for bugs that could corrupt your
event file. Upgrade before your next event, and take one minute to check any
event you have already run.**

FreePair edits your `.sjson` file in place: it changes the fields it manages
and leaves everything else exactly as it found it, so that details FreePair
does not display still survive a save. To do that it has to know which row is
which player, and which section is which — and until this run of releases it
worked that out from things that move. Players were identified by their seed
number, which re-seeding changes by design. Sections were identified by their
name, which renaming changes.

The consequence was that ordinary actions — re-seeding a roster before round
1, editing a rating, adding a late entry, renaming a section — could write a
player's details onto the row next to them, or a section's details into the
section beside it. The most serious form of this moved US Chess, FIDE, CFC
and NWSRS ID numbers onto the wrong players. **The US Chess ID is the identity
a rating report is submitted under**, so an affected event could have reported
games against the wrong member numbers.

**What to do:** open any event you have run recently, look at a few ID numbers
on the Roster tab against the players they belong to, and save. Saving with
this build writes each player's own details back where they belong. It cannot
repair an event that was already saved wrong under an older build, because the
incorrect values are what the file now contains — which is why it is worth
checking before you submit.

Nothing about this affects a file you have not opened yet, and none of it
requires you to redo work.

## What's new

**Sections now keep their own identity, the way players already do.** Each
section carries a permanent, invisible identifier, written the first time
FreePair saves the file and never changed again. Renaming sections — including
swapping two names, which used to trade their contents from the second save
onward — no longer moves anything between them.

**Deleting a section and reusing its name no longer leaves a ghost.** If you
removed a section and gave its name to another one in the same sitting, the
removed section could survive in the file: two sections with the same name,
one of them stale. It is now removed properly.

**Section order is preserved more reliably.** Moving sections up and down
previously relied on matching them by name, and now uses the same permanent
identity.

**Everything on a player's row travels with the player** (from the previous
release). Re-seeding, rating edits, late entries and deletions no longer leave
IDs, ratings or other details behind on the row. That includes details
FreePair does not itself display, such as age — which matters for age-prize
eligibility.

**Deleting a player deletes the right one** (from the previous release). Since
everyone below a removed player is renumbered, the removed player's seed
number instantly belonged to somebody else. Removal now follows the player,
not the number.

## Installer

Windows x64, macOS (Apple silicon and Intel) and Linux x64. The installer
bundles the .NET runtime, the pairing engines and the user guide — nothing
else to install. Run it and FreePair updates in place, keeping your events,
settings and recent-events list.

## Compatibility

The new section identifier is stored under a `FreePair …` key, the same kind
FreePair already uses for its own settings. SwissSys and NA Chess Hub ignore
keys they do not recognise, so files continue to open in all three. Older
FreePair builds ignore it as well.

Existing events pick the identifier up automatically the next time FreePair
saves them. There is nothing to configure.

## Known limitations

**An event already saved wrong cannot be repaired automatically.** FreePair
writes correct data from this build onward, but it has no way to know what an
already-corrupted file should have contained. This is why the check above is
worth a minute.

**Pairing fidelity.** FreePair's USCF engine is validated against a large
real-world SwissSys corpus and reproduces the great majority of pairings
exactly, reaching 100% on many representative events. The remaining
differences are in areas where the rules leave the director discretion —
board ordering within a score group, and which player receives a bye when
more than one is equally eligible. They do not affect the legality of a
pairing.
